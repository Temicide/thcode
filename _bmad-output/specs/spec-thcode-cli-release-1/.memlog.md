- (decision) Historical Windows-only, hosted-request-path, multi-provider, three-demo, structured-action-repair, and optional-cache proposals are superseded by the final PRD and Architecture Spine.
- (capability) CAP-1: A Thai or Thai-English developer can globally install and launch thcode on supported native Windows and macOS, connect separate Typhoon and AI-for-Thai credentials through protected flows, and see evidence-backed connection state; success is clean install plus passing live checks without credential exposure.
- (capability) CAP-2: A user can ask Typhoon in Thai or mixed Thai-English to complete a bounded local observe-act-verify task with controlled workspace and command tools; success is the C++ Hello World fixture compiling and executing with expected output on both release platforms.
- (capability) CAP-3: A prompt can select and invoke T-OCR, Speech-to-Text, Extract Address, or Named Entity Recognition through the local harness while the remaining catalog stays visibly non-invokable; success is four repeatable prompt-driven service flows with attributable evidence and no false-capability invocation.
- (capability) CAP-4: A user can understand deterministic remote failures, see quarantine scoped to the proven configuration, correct the condition, and explicitly retest; success is four service-specific recovery fixtures plus one shared-key failure fixture without unrelated-service disablement.
- (capability) CAP-5: A user can control Work Mode, Permission Profile, approvals, sensitive transfers, and durable Boundary Expansions while the local PEP independently enforces hard boundaries; success is zero unauthorized mutations, workspace escapes, or material transfers in release validation.
- (capability) CAP-6: A user can create, inspect, restore, and delete machine-local Saved Sessions while full transcript history remains separate from bounded Active Model Context and temporary authority resets; success is cross-platform restoration and context fixtures with no silent workspace rebinding or protected-content loss.
- (capability) CAP-7: A user can resume truthfully after an interrupted remote request and safely roll back attributable built-in file changes within bounded retention; success is crash-recovery and rollback fixtures preserving uncertainty, later edits, encryption, caps, and honest partial outcomes.
- (capability) CAP-8: A user can inspect persistent status, action previews, activity, provenance, context usage, service contribution, verification, and truthful next steps in the terminal; success is accessible narrow-terminal evidence for every significant action without secret leakage or model-generated contradiction.
- (constraint) Release 1 supports Typhoon as the only reasoning model and calls Typhoon plus four reviewed AI-for-Thai services directly from the local CLI; no hosted request path or silent dependency fallback is allowed.
- (constraint) Supported execution is native Windows 11 25H2+ with Windows Terminal and PowerShell, and macOS 14+ with Terminal and zsh; Node.js 22+ and npm global distribution are mandatory, with Node.js 24 LTS clean-machine validation.
- (constraint) Remote output is untrusted proposal data; one local PEP is the sole effect authority and must fail closed when workspace, command, process, network, quota, credential, consent, or platform enforcement cannot be proven.
- (constraint) Credentials remain in OS credential facilities, are identity- and host-bound, never enter model context or product persistence, and sensitive persisted content uses authenticated encryption with explicit key lifecycle.
- (constraint) Every authoritative operation, effect, event, artifact, health transition, cache reuse, interruption, and rollback result is versioned, attributable, crash-consistent, sanitized, and uncertainty-preserving.
- (constraint) User configuration is declarative and non-executable; adapters, slash commands, capability metadata, and protocol mappings are reviewed product code or data, and invalid structured proposals are rejected after one local validation pass without model repair.
- (constraint) The architecture must preserve a headless CoreApp behind CoreProtocolV1, inward ports-and-adapters dependencies, a persisted Session aggregate, fresh Runtime Activation authority, and an Ink UI that cannot bypass application policy.
- (decision) Non-goals include frontier-agent parity, alternate reasoning providers, full-catalog invocation, unsupported platforms and shells, GUI/web/mobile/IDE surfaces, Git status/diff integration, silent dependency installation, cloud session portability, executable extensions, protocol repair, automatic retry of uncertain effects, and rollback claims for untracked effects.
- (assumption) Users can obtain separate working Typhoon and AI-for-Thai credentials entitled for all four launch services.
- (assumption) AI-for-Thai launch contracts remain stable enough for reviewed mappings, live health checks, prompt routing, deterministic fixtures, and content-hash evidence reuse.
- (assumption) Supported OS credential facilities and encrypted local persistence can meet the confirmed credential, session, evidence, cache, and rollback boundaries.
